# 设计决策摘要

本文件汇总项目中几个关键取舍的**理由**。完整论证见 `eval/` 下的实验记录，
踩坑过程见 [`失败案例集.md`](失败案例集.md)。

## 1. 为什么不用 LangChain

需要精确控制流程每一步（阈值、判定逻辑、块数）来做消融实验；
框架的抽象层会让变量难以隔离，出问题也难以定位到具体环节。

## 2. 为什么逐块判定而不是拼接判定

把所有候选块拼成一段再问一次，实测拒答判断准确率 79%；
改为逐块提问后提升到 93%。多块混在一起时模型易被无关内容干扰。

## 3. 为什么最终放弃 Cross-Encoder 重排

重排显著提升检索指标（Recall@1 0.446→0.623），但端到端指标下降。
根因是链路中存在两套分数口径（稠密相似度 vs 重排分数），
下游阈值仍按稠密分数判断，导致「越重排越容易被拒」。
修正口径后过拒数仍未改善 → 说明瓶颈在判定环节而非检索。

## 4. 为什么块大小取 400–600 字

过小块上下文不完整、检索到也无法回答；过大块语义被稀释、噪音变多。
首版切分有 67.9% 的块小于 400 字（碎片化），改用「递归切分 + 自底向上合并」后，
69% 的块落在 400–600 区间。

## 5. 为什么用 FAISS IndexFlatIP

语料规模仅 286 块，精确检索耗时毫秒级；
IVF/HNSW 等近似索引在这个量级只会引入调参负担与精度损失。

## 6. 阈值为什么是 0.45 与 0.62

在 dev 集上做阈值扫描标定：0.45 用于初筛（低于此直接拒答），
0.62 用于早停（高于此跳过 LLM 判定直接放行，节省一半以上判定耗时）。
0.45 附近的安全区间仅约 0.0019 宽，说明该值非常敏感，继续微调即为过拟合。
