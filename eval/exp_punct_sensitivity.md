# 查询标点敏感性实验（阶段三·前置实验）

**实验日期**：2026-10-04  
**实验目的**：量化"用户输入的表层形式（标点）"对检索与判定的影响，判断是否需要做查询归一化  
**测试集**：`eval/data/questions.csv` 的 dev 子集（61 题）  
**数据文件**：`eval/data/exp_punct_sensitivity.json`（61 题 × 两种问法）

---

## 一、实验动机

在端到端验收中偶然发现：**同一问题，只差一个全角问号，系统行为完全反转**。

```
考试不及格可以补考吗     → rank1 = 0.6423 ≥ 0.62 → 触发早停 → 直接放行 → ✅ 正常回答
考试不及格可以补考吗？   → rank1 = 0.6145 < 0.62 → 走逐块判定 → 3 块全判 NO → ❌ 拒答
```

差异仅一个标点，rank1 分数变化 0.0278，跨过了早停阈值 0.62，判定结果完全反转。

**这引出一个必须回答的问题**：这是个别现象，还是普遍性问题？

---

## 二、实验设计

对 dev 集 61 题，每题各跑两种问法：

| 变体     | 问法                             |
| ------ | ------------------------------ |
| A（原问法） | 评估集原文，**均带全角问号**               |
| B（去标点） | 去掉首尾标点（`？?。.！!，,、；;：:…～~` 与空白） |

测量指标：rank1 分数、早停触发率（阈值 0.62）、Recall@5、top-10 排序是否变化。

实验脚本：`scripts/_devtools/exp_punct_sensitivity.py`（纯检索，61 题耗时约 1 秒）

---

## 三、实验结果

### 3.1 rank1 分数：系统性上升

| 项            | 数值                         |
| ------------ | -------------------------- |
| 去标点后分数**上升** | **60/61 题**，平均 **+0.0191** |
| 去标点后分数下降     | 1 题，平均 −0.0001             |
| 平均变化         | **+0.0188**                |

### 3.2 早停触发率：净收益 +4 题

| 变体    | 早停触发      | 占比        |
| ----- | --------- | --------- |
| A 原问法 | 34/61     | 55.7%     |
| B 去标点 | **38/61** | **62.3%** |

**由「不早停 → 早停」共 4 题，且全部是此前的过度拒答题**：

| qid  | 问题                | A      | B          |
| ---- | ----------------- | ------ | ---------- |
| q019 | 什么情况下会被学校退学？      | 0.6168 | **0.6330** |
| q045 | 实验室安全出问题找谁负责？     | 0.6196 | **0.6410** |
| q051 | 实验室出事故了怎么处理？      | 0.6199 | **0.6360** |
| q078 | 考试作弊被处分了，还能顺利毕业吗？ | 0.6087 | **0.6261** |

**由「早停 → 不早停」0 题** —— 即去标点只改善、不损害早停判定。

### 3.3 ⚠️ Recall@5：反而下降

| 变体    | Recall@5    |
| ----- | ----------- |
| A 原问法 | **0.9123**  |
| B 去标点 | 0.8860      |
| 变化    | **−0.0263** |

发生变化的仅 3 题，但幅度极端：

| qid  | 问题              | Recall@5 变化       | gold 排名变化           |
| ---- | --------------- | ----------------- | ------------------- |
| q001 | 软件工程专业毕业要修多少学分？ | 1.000 → **0.000** | rank 2 → **rank 6** |
| q045 | 实验室安全出问题找谁负责？   | 1.000 → **0.000** | rank 5 → rank 6     |
| q076 | 体测没达标，会影响评奖学金吗？ | 0.500 → **1.000** | rank 6 → rank 5     |

### 3.4 ★ 机制分析：这不是"检索变好"，而是"扰动"

进一步的机制验证（`scripts/_devtools/verify_affine_shift.py`）：

| 项                  | 数值                    |
| ------------------ | --------------------- |
| top-10 排序**完全相同**  | 仅 14/61 题             |
| top-10 排序发生变化      | **47/61 题**           |
| 同一批候选中分数差均为正       | 60/61 题（平均下界 +0.0128） |
| **平均平移量**          | **+0.0174**           |
| **同一题内部分数差极差（平均）** | **0.0093**            |

**结论**：去标点让**所有候选分数整体上升**（近似平移），但**上升幅度不均**（题内极差约 0.009），因此把原本紧挨着的候选**搅乱顺序**。

**关键对照 —— q001 的 top-5 分数分布**：

```
A 原问法: 0.7151  0.7059★  0.7054  0.7045  0.7025     （★ = gold，rank 2）
B 去标点: 0.7432  0.7353   0.7342  0.7320  0.7309     （gold 掉到 rank 6）
          +0.0281 +0.0294  +0.0288 +0.0275 +0.0284
```

**前 5 名的分数只相差 0.005**，而标点带来的扰动是 0.009 量级 —— 足以重排整个列表。

## 四、结论与决策

### 4.1 决策：**不采用"去标点"作为优化**

理由（四项指标互相矛盾，且效应性质是"扰动"而非"改进"）：

| 维度           | 判断                           |
| ------------ | ---------------------------- |
| rank1 分数     | ✅ 系统性上升 +0.019               |
| 早停触发         | ✅ +4 题，0 题变差                 |
| **Recall@5** | ❌ −0.026                     |
| **排序稳定性**    | ❌ 47/61 题 top-10 顺序被打乱       |
| **效应规模**     | ❌ 0.019 与候选间分差（0.005）**同量级** |

**根本问题**：该效应**幅度小、方向不可预测**（哪题变好、哪题变坏无规律），用召回与排序稳定性换取早停收益，不划算。这与本项目已记录的教训一致 —— **不应为在 dev 集上偶然成立的窄效应改动核心逻辑**。

### 4.2 更重要的发现：绝对阈值在分数密集区不可靠

本实验暴露出一个**比标点更本质**的问题：

> 早停阈值 0.62 是一个**绝对相似度阈值**，而实测候选之间的分数差常低至 **0.005 量级**，  
> 而任何微小扰动（一个标点、改一个字、换个同义词）都能造成 **0.009 量级**的位移。  
> **因此阈值附近的判定本质上是噪声驱动的。**

这与本项目已有的另一发现（案例 16：单一向量相似度阈值无法可靠判定"能否回答"）**互为印证**，并进一步给出了量化依据。

**可能的改进方向（留待后续实验验证）**：

- 用**相对判据**替代绝对阈值，如 top1 与 top-k 的分数比、或与结果集分数分布的偏离度
- 引入 **Cross-Encoder 重排**，用专门的交叉编码器获得更稳定的排序信号

### 5.2 可直接引用的结论

> 实验表明，用户输入的表层形式（标点）会系统性地影响稠密向量检索的相似度得分：去掉首尾标点后，61 道测试题中有 60 题的 top-1 相似度平均上升 0.019。然而该效应并非检索能力的提升 —— 同一批候选上的分数增幅不均（题内极差约 0.009），导致 47/61 题的 top-10 排序发生改变，Recall@5 反而下降 0.026。这说明**在候选分数密集（分差约 0.005）时，检索排序对微小扰动高度敏感**，基于绝对相似度阈值的判定缺乏鲁棒性。

### 5.3 对 E3（重排消融）实验的支撑

本实验是继以下两例之后，**第三个支持引入重排的实证**：

| # | 实证                             | 结论              |
| - | ------------------------------ | --------------- |
| 1 | 案例 16：单一阈值无法分离正确/错误命中          | 需要二次判别          |
| 2 | 国家奖学金问题：答案块排第 3 位，模型只读前两块      | 需要更可靠的排序        |
| 3 | **本实验：0.005 的分差 vs 0.009 的扰动** | **绝对阈值在密集区不可靠** |

## 六、实验局限

- 仅测试了"去首尾标点"一种归一化方式，未测试其他查询改写策略（同义替换、去停用词、口语转书面语）
- 仅在 dev 集（61 题）上验证，样本量有限；3 道 Recall 变化题即主导了整体指标
- 未测试中英文混排、数字与单位等更复杂的表层形式差异
- 未评估该效应对**生成**环节的间接影响（本实验只测检索层）
