# E3 重排消融实验（阶段三·第三批）

**实验日期**：2026-10-04
**实验目的**：验证 Cross-Encoder 重排能否改善检索排序、拒答能力与排序稳定性
**测试集**：`eval/data/questions.csv` 的 dev 子集（61 题）
**数据**：`eval/data/eval_runs.csv`（run_id: `20261004_2001_dev_b3_rerank`、`20261004_2008_dev_b3_rerank_top10`）
**模型**：`bge-reranker-base`（本地 `models/bge-reranker-base`，1.08 GB）

---

## 一、实验设计

| 配置 | 说明 |
|---|---|
| **b3_full** | 现有系统（无重排）：稠密召回 top-20 → top-5 → 阈值初筛 → 逐块判定 → 生成 |
| **b3_rerank** | 稠密召回 top-20 → **Cross-Encoder 重排** → top-5 → 同上 |
| b3_rerank_top10 | 同上，但喂判定的块数改为 10 |

**唯一变量是"是否重排"**，其余逻辑（阈值、判定、拒答守卫、引用编号）完全不变。

### 1.1 实验动机（三条既有实证，非"试试看"）

| # | 实证 | 数据 |
|---|---|---|
| 1 | 单一阈值无法分离（案例16） | 正确命中 0.5629–0.7321 vs 错误命中 0.6048（落在正确区间内） |
| 2 | 国家奖学金问题 | 答案块排 rank3，生成模型只读前两块 → 漏答 |
| 3 | 查询标点敏感性（案例22） | 候选分差 0.005 vs 扰动 0.009；47/61 题排序被改变 |

## 二、实验结果

### 2.1 检索层：重排显著有效 ✅

| 指标 | b3_full (n=56) | b3_rerank (n=57) | 变化 |
|---|---|---|---|
| Recall@1 | 0.4464 | **0.6228** | **+0.1764（相对 +39.5%）** |
| Recall@3 | 0.7589 | **0.8246** | +0.0657 |
| Recall@5 | 0.9107 | 0.9123 | +0.0016 |
| Recall@10 | 0.9821 | 0.9561 | −0.0260 |
| **MRR** | 0.6490 | **0.7789** | **+0.1299（相对 +20.0%）** |
| gold_doc_hit@5 | 1.0000 | 1.0000 | — |

> （b3_full n=56 因 q023 早期版本触发上下文溢出而失败；该缺陷已单独修复）

**gold 块排名提升**：平均名次 **2.20 → 1.86**；被提前 20 题 / 被推后 10 题 / 不变 26 题；落入 top-3 的题数 **45 → 49**。

### 2.2 端到端：反而变差 ❌

| 指标 | b3_full | b3_rerank | 变化 |
|---|---|---|---|
| tp / fp / fn / tn | 4 / 15 / 0 / 42 | 4 / **18** / 0 / 39 | fp +3 |
| **拒答查准率 P** | **0.211** | 0.182 | **−0.029** |
| 拒答查全率 R | 1.000 | 1.000 | — |
| 拒答 F1 | 0.348 | 0.308 | −0.040 |
| 可答侧放行率 | 0.737 | 0.684 | −0.053 |
| 平均总耗时 | 4494.6 ms | 4733.9 ms | +239 ms（+5.3%） |

**15 道原有过度拒答题**：重排后**仅恢复 1 道**（q018），14 道仍拒答。
**新增 4 道反向恶化**（原本可答 → 重排后拒答）：q032、q052、q056、q072。

### 2.3 排序稳定性：变差 ❌（单次扰动，结论需谨慎）

| 指标 | 无重排 | 有重排 |
|---|---|---|
| top-5 序列完全一致 | 36/61 (0.590) | **18/61 (0.295)** |
| top-5 集合一致 | 54/61 (0.885) | 38/61 (0.623) |
| rank1 发生变化 | 1/61 | 4/61 |

> **注意**：该结论基于**单次扰动实验**（原问法 vs 去首尾标点），且仅 18 题落入"序列一致"。
> 趋势方向可信，但样本量小，应在论文中标注为**探索性观察**，不作强结论。

### 2.4 跨文档类（cross）：检索提升明显，拒答无改善

| 指标 | b3_full | b3_rerank | top10 |
|---|---|---|---|
| Recall@1 | 0.125 | **0.375** | 0.375 |
| Recall@3 | 0.375 | **0.500** | 0.500 |
| Recall@5 | 0.500 | **0.750** | 0.750 |
| MRR | 0.521 | **0.875** | 0.875 |
| 过度拒答 | 3 | 3 | 3 |
| 可答侧放行率 | 0.250 | 0.250 | 0.250 |

cross 类 4 题中 3 题过拒（q076/q078/q080），重排把 gold 提前（q076: 2→1、q080: 4→2），**但判定仍全判 NO**。

### 2.5 b3_rerank 与 b3_rerank_top10 完全相同

两者在 recall@5 / mrr / refused 三项上 **61/61 题完全一致**。

**原因**：`verify_answerable(max_check=3)` —— 无论送入 5 块还是 10 块，判定器都只看前 3 块，而两档重排后的 top-3 相同。

→ **"扩大送入判定的块数"这条优化路径本身无效；真正的杠杆是 `max_check`。**

## 三、★ 机制分析：两个此前未发现的缺陷

### 3.1 缺陷一：重排路径的分数口径不一致（已修复）

**现象**：q052「国家奖学金一年给多少钱？」重排前正常回答（含"10000元"），重排后变为拒答。

**排查**：

| 配置 | rank1 | score（稠密相似度） | rerank_score | 结果 |
|---|---|---|---|---|
| 无重排 | gjjxj_2026_0002 | **0.6572** | — | ≥0.62 → 早停放行 → ✅ 答出 10000 元 |
| 重排后 | gjjxj_2026_0001 | **0.6150** | **0.9546** | <0.62 → 落到 LLM 判定 → ❌ 拒答 |

**根因**：`src/reranker.py` 把重排分数存入独立的 `rerank_score` 字段，**但 `score` 字段仍是该块的稠密相似度**。而下游两道门限——阈值初筛（`SCORE_THRESHOLD=0.45`）与早停（`0.62`）——**全部读 `score`**。

重排的作用恰恰是"纠正稠密的错误排序"，因此**被提上来的块，其稠密分数往往天然偏低**：

```
dev 61 题中，重排后有 30 题（49%）的 rank1 稠密分数 < 0.62
→ 这半数题全部落到 LLM 判定
```

**后果**：出现「**重排越正确，越容易掉进 LLM 判定**」的反常现象。

**修复**：
- `verify_answerable` 新增 `allow_early_stop` 参数（默认 `True`，不影响既有路径）
- `is_answerable` 新增 `use_rerank` 参数（默认取 `self.use_rerank`）；
  重排路径**跳过基于绝对分数的两道门限**，直接交给 LLM 逐块判定
- 理由：这两个阈值都按稠密相似度标定，与重排后的排序**量纲不可比**

**修复后仍有 4 道题无法恢复** —— 引出缺陷二。

### 3.2 ★ 缺陷二：判定器对某些措辞组合"稳定地判错"

修复口径后，过度拒答**未改善**。进一步做定向实验（答案块单独喂给判定器）：

```
q052  答案块 gjjxj_2026_0002 含「每生每年10000元」，单独喂判定器 → 仍判 NO
q032  答案块 kshgl_2020_0003 含「成绩公布后两周内提出申请」（且为 rank1）→ 仍判 NO
```

**随即做判定器健康检查与重复性测试**（`scripts/_devtools/check_judge_health.py`、`check_judge_stability.py`）：

| 问题 + 资料 | 期望 | 5 次输出 | 判定 |
|---|---|---|---|
| 国家奖学金一年给多少钱？+「每生每年10000元」 | YES | 5/5 YES | ✅ |
| 本科一般读几年？+「标准学制为4年，修读年限为3-6年」 | YES | 5/5 YES | ✅ |
| 体测要跑多少米？+「男生1000米，女生800米」 | YES | 5/5 YES | ✅ |
| **对成绩有疑问怎么查卷？+「成绩公布后两周内提出申请」** | YES | **5/5 NO** | ❌ |
| **国家奖学金和国家励志奖学金能同时拿吗？+「不能同时获得国家励志奖学金」** | YES | **5/5 NO** | ❌ |
| 图书馆几点关门？+「学生应当遵守学校规章制度」 | NO | 5/5 NO | ✅ |

**结论**：
- 判定器**输出完全稳定**（0/4 题不稳定）—— **不是随机性**
- 但它**稳定地在某些措辞组合上判错** —— 答案明确存在于资料中，仍返回 `结论：NO`
- 这是**小参数模型（3B）判定能力的边界**，且与措辞的表面形式相关

**影响**：过度拒答的根因**在判定器**，不在检索、不在排序。这解释了为何重排无法改善拒答查准率 —— **重排只改排序，改不了判定**。

## 四、结论与决策

### 4.1 决策：**暂不启用重排**（`RERANK_ENABLED` 保持 `False`）

依据：

| # | 依据 |
|---|---|
| 1 | 本批最关心的指标（拒答查准率）**未改善反而下降**（0.211 → 0.182） |
| 2 | 排序稳定性变差（序列一致率 0.590 → 0.295）—— 对表层扰动更敏感 |
| 3 | 检索排序的提升（Recall@1 +39.5%、MRR +20.0%）**未转化为端到端收益**（可答侧放行率 0.737 → 0.684） |
| 4 | 代价 +239 ms/题（+5.3% 总耗时） |

### 4.2 ★ 但本实验的核心价值：把"瓶颈在判定器"从推论变成**受控实验证明**

| 层次 | 证据 |
|---|---|
| **检索侧** | 已证明足够：gold 平均名次 1.86、top-3 覆盖 49/56、cross 类 MRR 0.875 |
| **排序侧** | 重排把排序进一步优化，端到端反而变差 → **排序不是瓶颈** |
| **判定侧** | 答案块单独喂入仍判 NO（5/5 稳定）→ **判定器是瓶颈** |

→ **继续优化检索/排序不会改善拒答；需改判定环节。**

### 4.3 下一步优化方向（需人工决策）

| 方向 | 说明 | 风险 |
|---|---|---|
| **提高 `max_check`** | 当前只看 3 块；实测改成 10 块时两档结果完全相同，说明 3 是硬瓶颈 | 判定耗时线性增加（每块约 2.2s） |
| **改判定 Prompt** | 当前 Prompt 的规则表述可能诱导保守判定 | 需重新验证鲁棒性（曾因改 Prompt 引入回归） |
| **用重排分数作判定特征** | 把 `rerank_score` 作为辅助信号参与判定 | 引入新参数，有过拟合风险 |
| **换更强的判定模型** | 与课题"本地 3B 模型"的硬件约束冲突 | 违背课题设定 |

**建议**：优先做「提高 `max_check`」的消融（成本低、可控），并在 dev 集验证；Prompt 改动需谨慎（有前车之鉴）。

### 5.2 可直接引用的结论

> 消融实验表明，引入 Cross-Encoder 重排后，检索排序指标显著提升（Recall@1 由 0.446 提升至 0.623，相对提升 39.5%；MRR 由 0.649 提升至 0.779，相对提升 20.0%），但其端到端收益为负：拒答查准率由 0.211 降至 0.182，可答侧放行率由 0.737 降至 0.684。
>
> 机制分析表明，这是两个层次的原因叠加所致：其一，重排改变了候选排序，但下游的绝对分数门限（阈值初筛 0.45、早停 0.62）仍作用于【稠密相似度】字段，而重排提升上来的候选其稠密分数往往更低（dev 集 49% 的题目出现此现象），导致"重排越正确、越容易进入 LLM 判定"；其二，在修正上述口径不一致后，拒答表现仍未改善 —— 定向实验显示，**即使将包含明确答案的文本块单独提交给判定器，模型仍有稳定判错的情形（同一输入重复 5 次全部返回"不能回答"）**。
>
> 由此得出本课题关于优化路径的重要结论：**在检索与排序已达到足够水平（gold 块平均排名 1.86、top-3 覆盖率 49/56）的前提下，继续优化检索或引入重排均不能改善系统的拒答表现；瓶颈位于判定环节。**

### 5.3 本实验的外部效度说明

- 重排配置固定（`bge-reranker-base`、top-20 → top-5），未做重排模型规模与 top-k 的网格搜索
- 排序稳定性结论基于单次扰动实验（去首尾标点），样本量为 18 题，属探索性观察
- dev 集 61 题，cross 类仅 4 题，分类指标的置信区间较宽
